## Тон тексту та обсяг результату (обов’язково узгодити з дипломом)

Зміст роботи має описувати те, що **вже є в репозиторії та в експлуатації** (чи принаймні факт реалізації станом на захист): тестовий набір, CI, конфіг деплою, YAML workflow, інфраскрипти тощо. Без намірів у майбутньому часі та без «ідей на продовження».

- [ ] **Жодних планів у тексті.** Прибрати або переписати формулювання на доконаний час / теперішній стан: замість «заплановано», «передбачено реалізувати», «можна розширити», «на наступному етапі», «у подальшому передбачається», «цей розділ є специфікацією для подальшої реалізації» — використовувати **«реалізовано», «налаштовано», «виконується», «покрито тестами», «оновлення відбувається через …»**, коли відповідні артефакти справді існують у проєкті.
- [ ] **Тести — як факт наявності.** Описувати наявні тести (шляхи `tests/…`, типи pytest, які сценарії перевірено), місце у CI або команду локального запуску; якщо частина лише дороблюється кодом до захисту — **спершу доробити репозиторій**, потім формулювання в тексті (текст не може відставати як «план», коли задача — опис готової роботи).
- [ ] **CI — як налаштований конвеєр.** `.github/workflows/…`: що саме робить workflow при push/PR (лінт, typecheck, build, pytest — за фактом), без майбутніх «налаштуємо».
- [ ] **Розгортання — опис існуючої схеми.** `deploy.sh`, `setup.sh`, Nginx, systemd, Certbot тощо: тільки як **чинна** конфігурація; не «YAML буде створено», якщо файл уже в репо.
- [ ] **Не включати блоки «Подальший розвиток»**, «Обмеження та можливі покращення», roadmap, backlog — включно з формулюваннями на кшталт «розглядається розширення», «доцільно доповнити».
- [ ] Виняток (аналітика, не розвиток продукту): у **SWOT** пункти «можливості / загрози» залишаються як огляд зовнішнього середовища — **але без перетворення їх у перелік дороблень роботи або «можна додати в застосунку» всередині висновку** окремою підрозділом майбутніх робіт.
- [ ] Пройтися grep/пошуком по `thesis_report.md`: `планув`, `буде`, `майбутн`, `потенційн`, `рекоменд`, `розширен`, `доповнити`, `наступний етап` — перевірити кожний збіг і виправити на **фактичний опис уже зробленого** або викинути абзац.
